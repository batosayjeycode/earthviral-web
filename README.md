# EarthViral

A global viral-news map. Every 3 hours a batch job reads public news feeds, groups articles about the same event, scores how much attention each story is getting, writes AI summaries that link back to every original publisher, and rebuilds the whole site as static pages.

- **Interactive world map**: a 3D globe or 2D map with country beacons tiered by viral score, and a country drawer.
- **Pre-rendered SEO pages**: story, country, category, country + category, region and topic pages, with structured data, sitemaps and social images.
- **No runtime server or database**: static HTML and JSON on Cloudflare Pages.

The full product and architecture spec is in [`PLAN_EARTH_VIRAL.md`](./PLAN_EARTH_VIRAL.md).

## Tech stack

| Layer | Choice |
| --- | --- |
| Site | [Astro 7](https://astro.build) static output, React 19 islands, Tailwind CSS v4, TypeScript (strict) |
| Map | MapLibre GL JS 6 and Natural Earth TopoJSON (`world-atlas`) |
| Data | JSON files validated by Astro content collections (Zod) |
| Batch pipeline | Plain Node 22 TypeScript (type stripping, no build step) |
| AI summaries | Gemini (`gemini-2.5-flash`) or OpenAI (`gpt-4o-mini`), with a non-AI fallback |
| Search | [Pagefind](https://pagefind.app), indexed after the build and run in the browser |
| Social images | satori and resvg, rendered at build time |
| Hosting | Cloudflare Pages, with data refreshed by GitHub Actions |

## Getting started

Requires **Node.js ≥ 22.23.4** (Astro 7's minimum).

```bash
npm install
npm run seed      # optional: write offline SAMPLE data (fictional stories)
npm run dev       # http://localhost:4321
```

To use real data instead of samples:

```bash
cp .env.example .env            # add GEMINI_API_KEY or OPENAI_API_KEY (optional)
npm run update:viral            # fetch, cluster, score and summarise (about 30 s)
npm run build && npm run preview
```

Without an API key, `update:viral` still runs. Summaries then list the original headlines instead of an AI synthesis, and the pages say so.

> **Search only works on a production build.** The Pagefind index is generated by `npm run build`. In `astro dev`, the search box tells you this.

### Batch flags

```bash
npm run update:viral -- --dry-run            # fetch, cluster and score; write nothing
npm run update:viral -- --provider none      # gemini | openai | none (default: whichever key is set)
npm run update:viral -- --max-new 60 --max-per-country 8 --max-ai 80
npm run update:viral -- --no-trends --no-gdelt
```

## How the batch works

`scripts/generate-viral-batch.ts` runs these steps:

1. **Collect.** It reads 29 curated RSS feeds (`scripts/lib/fetchers/rssSources.ts`), public Google Trends geo feeds and, optionally, GDELT. A failed feed is logged in `batch-meta.json` and skipped; it never fails the batch.
2. **Attribute.** It assigns each article to one of 41 tracked countries (`scripts/lib/countries.ts`), using the outlet's home country plus the places named in the headline. English and Bahasa Indonesia names are both recognised.
3. **Cluster.** It groups articles by TF-IDF headline similarity within each country, then merges fragments of the same event. New coverage attaches to existing stories, so **story URLs never change**.
4. **Score.** It computes the Viral Activity Score (VAS, 0–100):
   `0.55 × coverage + 0.45 × velocity + 0.15 × search bonus`.
   The constants live in `src/lib/scoring.ts` and also drive the public `/about/` page.
5. **Summarise.** It requests structured JSON from the LLM and validates it with Zod; invalid replies fall back to the non-AI summary. Calls are capped by `--max-ai`.
6. **Link and write.** It builds the related-story graph, validates every record, and only then replaces `src/data/generated/` and `public/data/`.

Stories leave the live map after **48 hours** without new coverage and are deleted after **30 days**.

## Configuration

All settings are optional environment variables. Anything left unset is simply omitted from the build: no empty ad boxes and no placeholder addresses. See [`.env.example`](./.env.example).

| Variable | Used by | Purpose |
| --- | --- | --- |
| `GEMINI_API_KEY` / `GEMINI_MODEL` | batch | Gemini summaries |
| `OPENAI_API_KEY` / `OPENAI_MODEL` | batch | OpenAI summaries |
| `PUBLIC_CONTACT_EMAIL` | site build | Address on `/contact/` and the legal pages |
| `PUBLIC_ADSENSE_CLIENT` | site build | Turns on ad slots and `ads.txt` (`ca-pub-…`) |
| `PUBLIC_ADSENSE_SLOT_STORY` / `PUBLIC_ADSENSE_SLOT_HUB` | site build | Ad unit IDs |
| `INDEXNOW_KEY` | site build and `npm run indexnow` | Publishes `/{key}.txt` and authenticates pings |

## Deployment

**Cloudflare Pages** (connect the Git repository):

- Build command: `npm run build`
- Output directory: `dist`
- Environment: `NODE_VERSION=22.23.4` or later, plus any `PUBLIC_*` and `INDEXNOW_KEY` values from the table above.

**GitHub Actions** (`.github/workflows/update-viral-batch.yml`) runs every 3 hours on the WIB clock (00:00, 03:00, … WIB) and can be started manually from the Actions tab. Each run:

1. Runs the unit tests.
2. Generates the batch.
3. Checks that the site still builds.
4. Commits `src/data/generated` and `public/data`; the push triggers the Cloudflare Pages deploy.
5. Waits for the deploy to go live, then pings IndexNow (best-effort).

Repository secrets: `GEMINI_API_KEY` and/or `OPENAI_API_KEY`, and optionally `INDEXNOW_KEY`. Optional repository variables: `GEMINI_MODEL`, `OPENAI_MODEL`.

## Conventions

- **Fonts.** Only freely licensed typefaces may be used (Sociolla's font policy). The site self-hosts Space Grotesk, Plus Jakarta Sans and JetBrains Mono, all under SIL OFL-1.1, via Fontsource. Fallback stacks use only generic CSS keywords such as `system-ui` and `monospace`.
- **Performance budget.** CLS must stay 0. Story and hub pages ship almost no JavaScript. On touch devices the MapLibre map loads on the first tap (desktops load it when the browser is idle), which keeps mobile Lighthouse Performance at about 98–100.
- **Data contracts.** `src/lib/types.ts` and `src/lib/schemas.ts` define every generated file. The pipeline validates against the same schemas the build uses.
- **Sample data.** Seed builds show a "Sample data — not real news" badge, mark every page `noindex`, and serve a `robots.txt` that disallows everything.

## Known limitations

- Summaries are English only; the data schema has one text field per summary.
- GDELT often rate-limits (HTTP 429). The pipeline works without it.
- Kompas, The Jakarta Post and The Star have no usable public RSS feed. Detik is read via `news.detik.com/rss`.
- Map beacons for neighbouring small countries (for example Malaysia and Singapore) can overlap, which is flagged by the desktop accessibility `target-size` audit.
- `npm audit` reports a moderate issue in `fflate`, a build-time-only dependency of satori. Runtime dependencies are clean.
